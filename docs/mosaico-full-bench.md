## 本次修复与边界

- V1.2 引脚与 PSRAM XIP 启动配置；保留 V1.0 配置。
- 识别已观察到的 Pocket 3 广播状态，保留设备型号和配对校验。
- 控制心跳接受已验证的合法参数组合，保留 CRC、身份和 pending 序号检查。
- 降低 OpenH264 初始 bitstream 预留，保留容量检查和上游扩容逻辑；不改变视频源编码格式。
- HEAD / JOYSTICK 都保留预览。临时控制保护暂停在停止确认及时到达时保留会话，恢复要求释放和新手势。
- 关键帧请求遇到临时动作或节流门禁时保留单槽请求，避免已受理请求被提前丢弃。
- 采用关闭本机 TX A-MPDU 的对照配置，RX 聚合保持；短时控制有改善证据，尚未证明消除所有无线故障。
- 对正常预览中完整匹配、单字节 `E1` 回复记录失败并进入原有有限恢复；不记成功、不放宽其他错误、不重试拍摄或运动。
- 本地 ACK 超时与相机 E1 共用 4/8/16 秒、最多三次恢复。成功需新的匹配 `00` 应答及新 IDR。

[DJI 公开 Payload-SDK](https://github.com/dji-sdk/Payload-SDK/blob/master/psdk_lib/include/dji_error.h) 将相机错误码 E1 定义为执行超时；这是跨产品解释线索，不是 Pocket 3 的专用协议规范。本项目采用的是针对实测帧的保守有界恢复。

## 已知问题

1. 长时间预览仍可能间歇停更、心跳超时或 Flow ACK 发送资源不足；重连后可恢复的观察不等于根因已消除。
2. 软件预览通常低帧率，且可能出现较长无新帧间隔，不承诺流畅视频或端到端低延迟。
3. 最新 E1 恢复的真实相机效果、各模式与拍摄组合、冷启动重复性仍需进一步验证。
4. 原有 250ms 输入 watchdog、300ms 停止确认、3s 心跳期限保持。无线失效时不能以本机成功发送代替物理停止证明。

原始串口、截图、Flash/NVS 备份和含设备身份的开发流水保持本地，不随源码或 Release 发布。
